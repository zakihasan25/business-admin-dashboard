# Client walkthrough: 60–90 seconds

**0–10s — The business question:** “What happens to other work when you move someone onto an at-risk project? This independently built demo makes that tradeoff visible. Every record is fictional.”

**10–25s — Explain the risk:** Enter the demo and open Delivery planner. “The model compares remaining project effort with weekday capacity. Each employee's project time is split across overlapping assignments, so the same hours aren't counted twice.”

**25–45s — Explore a recovery:** Select Customer portal redesign and click Load example. “This example extends the deadline and removes Reese Vale from Partner onboarding. The portal's gap closes, but onboarding loses capacity and becomes at risk.” Point to both estimates. “A manager can change the scenario rather than blindly accepting it.”

**45–65s — Deliberate application:** Enter a fictional rationale such as “Protect the portal deadline; review onboarding timing with its owner.” Review and apply the plan. “The project records update together, and the decision is saved with before/after records.”

**65–80s — Undo and trust:** Undo the plan. “Undo restores those records, but refuses to overwrite later edits. The assumptions and limits are visible. This illustrates frontend decision workflows, not a production forecasting or security system.”

**80–90s — Close:** “The same workspace supports employee and project editing, reporting, mobile, and dark mode. Everything runs locally as a static frontend.”
